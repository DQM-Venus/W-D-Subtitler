# W-D Subtitler 使用说明

## 1. 添加媒体

点击“添加文件”选择音频或视频。程序会使用 PyAV 探测音轨；带 `ja` 或 `jpn`
语言标签的音轨会被优先选择，否则使用第一条音轨。

“所选文件音轨”表示当前媒体中实际送入识别流程的声音轨道。双语视频、导演评论轨或
多声道封装文件可以通过下拉框切换音轨。

## 2. 识别设置

### 模型精度

- `float16`：GPU 推荐选项，速度和准确性平衡较好；
- `int8_float16`：减少显存占用，部分显卡上更适合大模型；
- `int8`：主要用于 CPU 回退或显存非常紧张的环境。

模型加载失败时程序会依次尝试较低显存方案和 CPU `int8`。

### 质量模式

- 快速：Kotoba 完整识别，Large-v3 只处理可疑片段；
- 高质量：Kotoba 与 Large-v3 分别识别完整音频，再比较候选；
- 两种模式都会对模型分歧片段追加一次扩大边界的局部识别。

### 日文热词

只填写已经确认的角色名、地名、组织名或作品专有词。热词只传给 Kotoba 首轮识别，
Large-v3 不继承热词，以保持候选独立性。不要粘贴完整文件名或长句。

## 3. AI 设置

### Large-v3 复核

提高识别可靠性。高质量模式耗时更长，并需要更多显存。

### AI 候选裁决

仅处理三次识别后仍有分歧的片段，必须同时启用 Large-v3 并填写 API Key。AI 无法
听到原始音频，只能根据候选、声学指标和上下文作保守判断。

### 翻译参考

单文件会提取结构化术语表，多文件会生成系列总纲。已确认术语会进入译文一致性检查；
无法确认的项目保留为待确认项。

## 4. 时间轴与导出

时间轴精修使用 Silero VAD，将字幕片段边界向附近语音边界轻量调整，也会尝试用可靠
静音点拆分没有标点的长句。它不会生成词级卡拉 OK 时间戳。

- SRT：适合播放器和视频编辑器；
- LRC：适合按时间显示的歌词或对白场景；
- 同名文件不会覆盖，程序会自动生成 `(1)`、`(2)` 等编号。

## 5. 取消、部分字幕与恢复

- 媒体解码和 ASR 收到取消后会尽快停止；
- 正在进行的 API 请求会等待本次 HTTP 调用结束，但不会进入下一批；
- 翻译未完成时保存 `.partial.srt` 或 `.partial.lrc`；
- 已翻译行使用译文，未翻译行显示 `[未翻译] 原文`；
- 下次处理相同媒体时，程序会提示继续断点、重新处理或取消；
- 成功完成后删除断点，未完成断点默认保留 7 天。

## 6. 常见问题

### CUDA 设备存在但无法加载模型

检查 CUDA 12 运行时、CTranslate2 和 NVIDIA 驱动是否兼容。程序会尝试
`int8_float16`，仍失败时回退 CPU `int8`。

### 术语提取无结果

这不一定是错误，可能表示文本中没有可靠的人名或专有术语。如果同时出现 API 错误，
请检查 Key、Base URL、网络和账户限额。

### 翻译出现 `[听不清]`

说明该行 ASR 声学置信度较低。翻译模型被要求只翻译现有原文，不根据剧情擅自补写。

### 为什么处理时间比音频时长短很多

GPU 上的 Faster-Whisper 可以显著快于实时播放速度。日志中的模型阶段耗时和整个文件
耗时统计口径不同，应以处理摘要的总耗时为准。
